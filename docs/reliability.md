# OpenWorkBot 运行与验证要求

## 1. 日志

- 工程事件：控制台及 backend/data/logs/app.log；5 MB 轮转，保留 5 份。
- 模型快照：log/model-io-<session_id>.jsonl，记录主/子调用；目录可配置，默认 10 MB 轮转。
- 快照含提示词、对话、工具参数和结果，可能携带敏感数据；不得提交 Git 或直接公开。
- 模型快照写失败仅记录告警，不阻断对话；摘要调用当前未纳入该记录与用量。

## 2. 干净环境

- 按 AGENTS.md，开发阶段不做 schema 迁移；测试从空库开始。
- 重建前停止相关服务、核对 DATA_DIR；backend/data/ 还包含工作区与日志，清空前确认全为可丢弃开发数据，避免误删用户文件。
- 未来验证使用独立临时目录及假模型；不得与真实数据共用目录。
- 不提交 .env、密钥、数据库、日志、缓存、依赖目录、构建产物与外部参考仓库。

## 3. 高风险边界

- 不实际执行删除、格式化、危险网络命令；相关逻辑使用 mock 或专用测试目录。
- 真实模型调用、费用与对外操作需明确授权；配置好密钥不等于授权运行评测。
- 无认证、无系统沙箱，不面向不可信用户开放；停止与重新生成不保证撤销副作用。

## 4. 验证与记录

- 当前旧测试套件已删除；npm test 与 pytest 配置存在残留，不能作为已有效验收的入口。
- 静态检查只证明所检查的文本/结构性质；构建、启动、业务测试与真实模型效果分别记录。
- 每次记录版本、范围、方法、结果和未覆盖项；未执行不标通过，功能 passing 必须附对应证据。
- 注释清理允许比较非注释 token、排除 docstring 的 AST、配置值及差异；这不等于运行测试。
- 代码、行为、配置变化同步当前文档；收尾更新 progress.md 和 feature_list.json，提交/push 遵守用户授权。
