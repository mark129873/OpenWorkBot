# OpenWorkBot 产品需求

## 1. 定位与状态

打造类OpenAI Dots 的自主智能员工, 面向个人与企业提供主动执行, 多智能体协同, 长期记忆, 工作流自动化的AI原生产品, 构建可自主规划, 自动调用工具, 自主迭代的超级Agent舰队

核心交互：用户始终和同一个助手聊天，助手在后台管理多个任务。

- 进入就打开主聊天：不再先选会话或点“新建会话”。
- 任务执行不锁住聊天：用户可以追问、修改要求，也能交代另一件事。
- 进展和结果回到主聊天；提示 Worker 简短回复，超过单条消息 16 KiB 时截断并提示；子 Agent 默认不单独露出。
- 需要确认时在主聊天询问：明确关联哪个任务，避免多个任务混在一起。
- 右上角设置可重置助手：目标为停止当前用户所有 Agent，删除旧聊天、任务、检查点、长期记忆和模型日志，再用空白会话开始；保留工作区。当前实现仍会归档旧数据。

底层不是把所有内容无限塞进一个上下文，应当分开：

- 主对话：你和助手持续沟通。
- 子助手：各自保存目标、执行状态和工作上下文。

## 2. 开发原则

- 优先形成简单可用版本；具体首版功能逐项确定，不把完整愿景当作已实现能力。
- RAG 独立运行，经本机 MCP 提供给后台 Worker；首版不做通用 MCP 管理。

## 3. 目标能力

| 能力 | 目标 | 当前基线 |
| --- | --- | --- |
| 自主执行 | 规划、调用工具、依据反馈调整并交付 | 有 Agent Loop 与任务板，独立 Goal Loop 仅在参考脚本 |
| 多 Agent | 按需分工、协调、汇总结果 | 最多三个后台 Worker，任务与上下文独立保存 |
| 上下文与记忆 | 控制上下文，跨任务保留有效信息 | 有历史回放与压缩，无跨会话长期记忆 |
| 主动与工作流 | 已授权的定时、事件任务及状态检查 | 无持久调度、定时或主动通知 |
| 工具扩展 | 原生工具、Skills、MCP 外部能力 | 有原生工具和 Skills，无通用 MCP 客户端 |
| 可靠性 | 权限、停止、记录、恢复与执行边界 | 有审批、记录及重启恢复；无系统沙箱 |

## 4. 交互与约束

用户提出目标，主助手首轮判断完整意图和首个动作，直接完成预计可快速处理的简单任务；复杂、耗时或适合并行的任务交给后台助手。进展和结果回到主聊天；需要补充信息或审批时询问用户。
聊天支持多文件上传至工作区，单文件不超过 100 MiB；同名直接替换。仅明确指定时将 PDF、TXT、Markdown 入知识库或更新索引，上传本身不解析、不入库。
知识库由后台 Worker 通过聊天导入、查看、移出和问答；移出及删除助手均保留工作区文件，删除助手也保留知识库。回答只覆盖用户的问题和影响结论的必要条件，暂不附引用编号或来源列表；证据不足时只回答有依据的部分。
模型通过环境变量选择 Anthropic 兼容接口或 OpenAI；主助手、后台助手与知识库使用同一配置，保留现有权限和恢复行为。
主动执行与自动迭代不得扩大授权；达到步数、资源或权限边界时停止并说明。
“自主迭代”首先指根据结果修正计划，不承诺自动训练模型或无限修改自身代码。
“面向企业”为目标定位；当前单用户、无登录，不宣称企业级多租户或生产部署能力。

## 5. 验收口径

现有代码不等于已验收。功能以明确行为、可追溯结果和实际验证为准；静态检查、构建、运行与模型质量分别记录。
测试与真实模型验证证据见进度记录；公开评测方案另行确定。
进度见 [progress.md](progress.md)，功能状态见 [feature_list.json](feature_list.json)。

## 6. 已确认改造方向

- 以 DeerFlow Gateway 为主体，保留主 Agent、后台 Worker 和 Shared State + Message Bus；引入多用户、长期记忆及 LangGraph SQLite 检查点。
- 延续现有前端，以 Agent Teams 示例扩展协调器；成功、失败或停止的任务在结果送达后清理、不归档，保留聊天结果、工作区文件及不含任务内容的去重标记。取消每团队累计 100 个请求和共享状态 20 条上限。
- 重置当前用户所有 Agent 和 SubAgent，删除其旧聊天、任务、检查点、长期记忆及模型日志，新会话不加载旧上下文；其他用户不受影响。每次新 Run 刷新长期记忆。
- 首版使用 LocalSandbox，禁用宿主命令；Docker 和 PostgreSQL 待用户后续确认。
- RAG 及其 MCP 接入暂不改造；具体设计和未理解的实现先同步用户。
