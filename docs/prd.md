# OpenWorkBot 产品需求

## 1. 定位与状态

打造类OpenAI Dots 的自主智能员工, 面向个人与企业提供主动执行, 多智能体协同, 长期记忆, 工作流自动化的AI原生产品, 构建可自主规划, 自动调用工具, 自主迭代的超级Agent舰队

核心交互：用户始终和同一个助手聊天，助手在后台管理多个任务。

- 注册或登录后进入主聊天：先加载最近消息，上翻加载更早记录，聊天保留至用户重置。
- 任务执行不锁住聊天：用户可以追问、修改要求，也能交代另一件事。
- 进展和结果回到主聊天；提示 Worker 简短回复，其最终结果超过 16 KiB 时截断并提示；子 Agent 默认不单独露出。
- 需要确认时在主聊天询问：明确关联哪个任务，避免多个任务混在一起。
- 右上角设置可重置助手：停止当前用户所有 Agent，删除旧聊天、任务、检查点、长期记忆和该用户的模型日志，再用空白会话开始；保留工作区。

底层不是把所有内容无限塞进一个上下文，应当分开：

- 主对话：你和助手持续沟通。
- 子助手：各自保存目标、执行状态和工作上下文。

## 2. 开发原则

- 优先形成简单可用版本；具体首版功能逐项确定，不把完整愿景当作已实现能力。
- RAG 独立运行；首版暂不向 Agent 提供 RAG 工具，不改 RAG 服务和数据，不做通用 MCP 管理。

## 3. 目标能力

| 能力 | 目标 | 当前基线 |
| --- | --- | --- |
| 自主执行 | 规划、调用工具、依据反馈调整并交付 | 有 Agent Loop 与任务板，独立 Goal Loop 仅在参考脚本 |
| 多 Agent | 按需分工、协调、汇总结果 | 每用户最多六个后台 Worker，任务与上下文独立保存 |
| 上下文与记忆 | 控制上下文，跨任务保留有效信息 | 有历史压缩和按用户隔离的长期记忆 |
| 主动与工作流 | 已授权的定时、事件任务及状态检查 | 无持久调度、定时或主动通知 |
| 工具扩展 | 原生工具、Skills、MCP 外部能力 | 有原生工具和 Skills，无通用 MCP 客户端 |
| 可靠性 | 权限、停止、记录、恢复与执行边界 | 有审批、记录及重启恢复；无系统沙箱 |

## 4. 交互与约束

用户提出目标，主助手首轮判断完整意图和首个动作，直接完成预计可快速处理的简单任务；复杂、耗时或适合并行的任务交给后台助手。进展和结果回到主聊天；需要补充信息或审批时询问用户。
聊天支持多文件上传至用户工作区，单文件不超过 100 MiB；同名直接替换。上传不解析、不入知识库，首版不开放 RAG 工具。
主助手、后台助手和记忆提取共用 OpenAI 兼容 Chat Completions 配置，保留现有权限和恢复行为。
主动执行与自动迭代不得扩大授权；达到步数、资源或权限边界时停止并说明。
“自主迭代”首先指根据结果修正计划，不承诺自动训练模型或无限修改自身代码。
“面向企业”为目标定位；当前只支持本机多用户，不宣称企业级多租户或生产部署能力。

## 5. 验收口径

现有代码不等于已验收。功能以明确行为、可追溯结果和实际验证为准；静态检查、构建、运行与模型质量分别记录。
测试与真实模型验证证据见进度记录；公开评测方案另行确定。
进度见 [progress.md](progress.md)，功能状态见 [feature_list.json](feature_list.json)。

## 6. 已确认改造方向

- 参考 DeerFlow Gateway 的功能和架构，在本项目自行重写并移植现有调度；保留 README 中主 Agent、后台 Worker 和 Shared State + Message Bus，引入多用户、参考 DeerMem 的长期记忆设计及 LangGraph SQLite 检查点。
- 单 Gateway 进程为每个用户管理独立运行时、调度队列和主助手，最多同时运行 6 个后台 Worker；主 Agent 和各 Worker 分别保存上下文，同一上下文同时只运行一个图，共享所属用户工作区。除已确认的新规则外，保留现有调度细则。用户可继续聊天，后台任务不因主回复结束、关闭页面、退出登录或切换账号而取消。
- 延续现有前端，以 Agent Teams 示例扩展协调器；成功、失败或停止的任务在结果送达且依赖和通知处理完成后清理、不归档，包括关联 Worker 检查点、已送达消息及不再使用的任务专属共享状态；保留聊天结果、工作区文件、长期记忆和不含任务内容的去重标记。未送达消息保留至确认或由主 Agent 处理，Worker 模型日志保留至用户重置。取消每团队累计 100 个请求、共享状态 20 条及 16,000 字节总量、最近团队消息 100 条和任务查询偏移 200 的限制。
- 主 Agent、所有 Worker 和后台记忆提取共用一组 OpenAI 兼容模型配置；上下文压缩沿用现有规则，各 Agent 独立压缩。不设置每 Run 16 条 / 64 KiB 累计输入上限及单根任务 12 个关联请求上限。
- 主 Agent 与所有 Worker 共用当前用户的一份长期记忆，只有主 Agent 可以写入；摘要用 JSON、事实用 Markdown，独立 SQLite FTS5 索引和 jieba 分词辅助查询。每用户最多 100 条事实，超出时按置信度保留前 100 条；静默 30 秒后提取，事实置信度至少 0.7，每次注入最多 2,000 token。后台提取按用户顺序处理、不阻塞聊天，内存队列异常退出时可能丢失待提取内容；每次新 Run 刷新，读取失败时不带记忆继续并提示用户。
- 重置当前用户所有 Agent 和 SubAgent，删除其旧聊天、任务、检查点、长期记忆及可确定归属的模型日志，新会话不加载旧上下文；其他用户不受影响。
- 用户使用账号名和密码自行注册、登录，无需邮箱；首版仅本机访问，用户要求密码明文保存。无法确认用户归属的旧模型日志保留并提示。
- 保留 build / edit / yolo 权限模式及现有文件操作审批，进行中和重启恢复的任务跟随用户切换后的模式。首版参考 DeerFlow LocalSandbox 自行实现本地沙箱，所有模式均 `allow_host_bash: false`，禁用宿主命令，包括旧 PowerShell 工具。数据库和长期记忆放在 `backend/data/`，用户工作区放在 `backend/workspaces/` 并忽略 Git；本机旧工作区已移至独立位置保存，不导入新用户工作区。Docker 和 PostgreSQL 待用户后续确认。
- RAG 服务及数据暂不改造，首版关闭 Agent 的 RAG MCP 工具，后续接入须用户确认；具体设计和未理解的实现先同步用户。
