# OpenWorkBot 产品需求

## 1. 定位与状态

OpenWorkBot 是用于展示 Agent 工程能力的开源通用数字员工项目，不以商业化或已有企业客户为前提。

目标：接收用户目标，自主规划、调用工具、按需协作，在权限与预算范围内持续执行，并交付可核验的结果。

本文描述待实现功能，不代表已经完成。当前仓库尚未迁入业务代码；law_agent_v2（law2）提供 Harness 能力参考，law_agent（law1）提供 LangGraph、Milvus、RAG 与评测能力参考。迁移前逐项确认复用边界，不直接复制两套完整系统。

## 2. 产品形态

- 一个仓库、一个用户入口；内部模块化，知识服务可独立运行和评测。
- 主 Agent 面向通用任务，不将法律、固定工作流或 RAG 写死在执行循环中。
- 通过 MCP 接入知识服务及其他工具；支持原生工具。
- 法律资料保留为演示与回归场景，底层支持通用知识库。
- 首批建议演示：跨文档研究与比较、表格数据分析、报告与工作区文件交付。具体演示数据后续确定。

## 3. Harness 核心功能

### 3.1 任务执行

- 接收目标，必要时澄清，生成并持续更新任务计划。
- 实现“决策—工具执行—观察—检查—继续或结束”的循环。
- 支持执行、暂停、等待用户确认、取消、失败、完成等状态；保留状态变更记录。
- 设置总轮次、时间、Token 与费用预算；耗尽时停止或返回明确标注的部分结果。
- 按错误类型有限重试，避免主循环、子 Agent 与 RAG 叠加造成无界重试。

### 3.2 工具与权限

- 统一工具注册、Function Calling 参数校验、结果格式、超时和错误处理。
- MCP 工具发现、连接管理与调用；工具故障不得阻断整个服务。
- 文件访问限定工作区；代码执行使用隔离环境及资源限制。
- 写入、外发、删除等操作按风险配置审批；未知权限默认不执行。
- 文档与工具返回内容视为不可信数据，不得覆盖用户目标或权限规则。
- 不把密钥写入日志、模型上下文或仓库。

### 3.3 多智能体协作

- 主 Agent 负责任务分派、进度管理、结果聚合与最终交付。
- 按需创建研究、分析、核验等子 Agent，不固定六个角色，不强制每个任务多 Agent 化。
- 子任务明确输入、输出、证据、权限与预算；独立上下文，限制嵌套深度和并发数。
- 支持并行执行、取消传播、部分失败处理和超时回收。
- 子 Agent 不能自行扩大授权；最终结论不能仅依赖另一个模型的“审核通过”。

### 3.4 上下文与记忆

- 按需加载工具说明、Skills 和相关资料，减少无关上下文。
- 压缩长历史，保留用户约束、任务计划、关键证据、未完成事项及产物引用。
- 区分会话上下文、任务状态、长期记忆；事实记录附来源与更新时间。
- 长期记忆支持查询、更新和删除；避免将未经验证的模型输出保存为事实。
- 工作流状态以结构化存储为准，不能用摘要或向量记忆替代。

### 3.5 持久化与恢复

- 持久化任务、子任务、工具调用、审批、检查点及产物元数据。
- 重启后恢复未完成任务；审批等待状态不得被恢复过程绕过。
- 写操作使用幂等键或结果核对，避免盲目重复产生外部副作用。
- 明确区分成功、失败与结果未知；结果未知先核验再决定是否重试。
- 首版优先单机存储方案，具体数据库选型在技术设计中确认。

### 3.6 主动执行

- 支持用户授权的定时任务、事件触发和待办状态检查。
- 心跳用于检查已授权任务，不无限生成新任务或持续调用模型。
- 实现触发去重、并发限制、取消和错过执行时间的处理规则。
- 重要结果、阻塞或确认需求才通知用户，避免重复提醒。

### 3.7 反馈迭代

- 首版：根据错误与验收反馈修正参数、补查证据、调整计划；限制迭代次数。
- 后续：保存经验证的任务经验或 Skills，经评测后启用。
- 不承诺自动训练模型或无限制修改自身代码；策略变更需版本、评测与回滚。

## 4. 知识服务：Agentic RAG 与图检索

### 4.1 文档与混合检索

- 支持文档导入、解析、分块、更新和删除；维护文档版本及稳定片段 ID。
- Milvus 承担向量与关键词混合检索，结合融合、去重和 Rerank。
- LangGraph 编排查询改写、子问题拆分、证据检查及有限补检；策略按需启用。
- 返回原文、文档与片段 ID、位置、版本及证据缺口，不只返回一段生成答案。
- 文档访问范围必须落实到检索与原文读取，不能只写在 Prompt 中。

### 4.2 GraphRAG 增强

- 从资料提取实体、关系及支持它们的原文；处理别名、重复和关系冲突。
- 支持受限关系遍历，将关联结果映射回原文，与混合检索结果融合精排。
- 图谱可随文档更新或删除；避免陈旧关系继续参与回答。
- 图检索可开关；先建立混合检索基线，再验证图增强的收益与成本。
- 图存储选型待定；不默认采用完整微软 GraphRAG 或全库社区摘要流程。

### 4.3 MCP 边界

- 建议能力：知识检索、原文读取、实体关系查询；具体接口在技术设计中定义。
- Harness 负责业务任务拆分和总预算；RAG 负责一次检索请求内部的规划与补检。
- Harness 保存会话与执行状态；LangGraph 保存检索过程状态；向量库与图存储保存知识索引。
- 使用任务 ID、调用 ID 串联追踪，避免双重维护完整会话与任务状态。

## 5. 用户入口与可观测性

- 提供任务对话、计划与进度、子任务状态、审批、取消及产物查看入口。
- 展示可解释的执行摘要和工具记录，不依赖展示模型内部推理。
- 记录模型版本、工具参数摘要、结果状态、错误、耗时与 Token 使用；敏感字段脱敏。
- 费用按可用价格配置估算，并区分估算值与实际账单。
- 支持导出可复现的任务与评测报告。

## 6. 评测与验收

以下为候选方案，数据版本、子集、运行费用及质量阈值需另行确定；尚未执行或取得成绩。

| 对象 | 候选公开基准 | 验证目标 |
| --- | --- | --- |
| RAG | MultiHop-RAG | 跨文档检索、答案与支持证据 |
| 多轮 RAG | IBM MTRAG | 追问、上下文承接与证据利用 |
| Harness | τ²-bench | 在模拟工具环境中完成多轮任务 |
| 工具专项 | BFCL | 函数选择、参数和调用行为 |
| 安全专项 | AgentDojo | 正常任务完成率与提示注入攻击成功率 |

- 基准适配器必须调用本项目执行循环；只运行官方默认 Agent 或底层模型不能当作 Harness 成绩。
- RAG 用公开语料自行建索引；参考答案与标注证据仅用于评测，不泄露给待测检索流程。
- 保留 law1 法律用例做回归，不把自建小集的结果视为生产准确率。
- 冻结调试集与保留测试集；报告数据版本、抽样方式、模型、预算与代码版本。
- RAG 关注证据召回、答案正确性、引用支持度；Harness 关注任务完成、权限遵守、恢复与成本。
- 超时、工具失败与未完成任务计入结果，不通过删掉失败样本美化分数。
- 规则断言、参考答案和必要的人工抽查结合使用；LLM Judge 仅作辅助。
- 工程测试覆盖中断恢复、MCP 断连、无效参数、重复触发、写入幂等、取消、权限拒绝、预算耗尽与子任务部分失败。
- 对比实验：混合检索／Agentic RAG／图增强；单 Agent／多 Agent。报告质量、耗时和成本，不预设复杂方案必然更优。

## 7. 分阶段范围

1. **执行基础**：迁移可复用 Harness，跑通单 Agent、工具、工作区、状态持久化、权限和日志。
2. **可靠协作**：实现子任务调度、隔离、恢复、上下文压缩和有限反馈迭代；接入 RAG 基线。
3. **主动与知识增强**：增加定时及事件任务、长期记忆和可开关图检索。
4. **验证展示**：完成公开基准适配、故障注入、对比实验和演示文档；评测随各阶段同步补充。

首版不覆盖完整浏览器自动化、邮件日历生态、企业多租户、无限自主运行或模型训练。后续扩展由实际需求和评测决定。

## 8. 项目交付标准

- 提供安装配置、架构边界、工具权限及数据流文档。
- 提供可复现的示例任务、运行轨迹、测试脚本与评测报告。
- 明确已实现、实验性、规划中功能；不虚构用户量、生产部署或提升比例。
- 对外模型调用、付费服务或评测运行按用户授权执行；本 PRD 不授予任何费用或部署授权。
