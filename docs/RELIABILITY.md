# OpenWorkBot — 运行与验证边界

## 数据保护

- 真实会话、工作区、密钥和日志不用于破坏性验证，不提交 Git。
- 未来验证使用独立临时目录与假模型；真实模型调用及费用另行授权。
- 删除数据库、覆盖用户文件或变更 schema 前明确数据影响；不默认清空整个 data 目录。
- 当前没有数据库迁移机制；后续是否引入迁移需设计确认，不沿用“永远不迁移”的历史约定。

## 日志

- 工程事件：控制台及 backend/data/logs/app.log，轮转 5 MB，保留 5 份。
- 模型调用：log/model-io-<session_id>.jsonl，默认 10 MB 轮转，可配置 MODELIO_DIR。
- 模型快照包含正文和工具参数，可能含用户敏感内容；不得入库或公开分享。
- 日志写失败不应误报任务成功；现有实现与已知缺口见 ARCHITECTURE.md。

## 当前验证状态

旧测试文件与历史测试报告已移除。当前无可运行的项目测试套件，本轮仅整理文件和文档，未验证安装、启动、构建、真实模型调用或功能正确性。
构建、Lint、启动检查与业务测试是不同验证层级；任何一项通过均不能替代其他项。
后续验证记录需写明代码版本、环境、命令、结果与未覆盖范围，不恢复旧进度流水账。

## 配置残留

- frontend/package.json 仍有指向已删除测试配置的 test 命令，当前不能使用。
- backend/pyproject.toml 与 uv.lock 仍含 pytest 等测试开发依赖及测试配置。
- 这些属于后续代码/依赖清理，本轮未修改清单或手工改写锁文件。

## 运行安全

仅监听本机；当前无认证与系统级命令沙箱，不暴露公网或不可信局域网。
停止是协作式检查，不保证立即终止已启动命令；重跑可能重复产生外部副作用。
模型和工具异常必须保留原因；未运行的验证只能标记未验证。
